SkillBridge AI

Architecture Analysis & Upgrade Plan · IBM Bob Better Bengaluru Challenge

1 · Existing Architecture

The starter is a clean, single-file Flask monolith with three minimal rule-based agents and one utility. Every component works correctly and is the foundation everything new will build on.

Entry point
app.py

Flask app, SQLite setup, 7 routes: /, /jobs, /api/match, /api/skill-gap, /assistant, /resume, /apply/<id>, /tracker, /health

Database
database.db (SQLite)

Two tables: jobs (id, title, company, location, job_type, skills, description) and applications (id, candidate_name, job_id, status, created_at)

Agent 1
agents/job_matcher.py

Set-intersection skill overlap scorer. Returns match %, matched skills, and missing skills. Sorted by descending score.

Agent 2
agents/skill_analyzer.py

Set-difference gap finder. Returns matched, missing, coverage %, and a flat list of "learn X" strings as roadmap.

Agent 3
agents/career_assistant.py

Keyword-rule reply generator. English and Kannada. Stubs: resume, interview, skills/learn/roadmap, and a generic fallback.

Utility
utils/resume_parser.py

Extracts text from PDF (pypdf), DOCX (python-docx), and TXT. Skill extraction by regex against 28 hardcoded known skills.

Templates
base / index / jobs / tracker

Jinja2 templates. base.html has sticky nav (Home, Explore Jobs, My Tracker). No resume-upload UI or dashboard yet.

Frontend
static/js/app.js + style.css

Vanilla JS with fetch. Handlers for job matcher and career assistant. Custom CSS design system with CSS variables.

3 · Step-by-Step Implementation Plan

Database schema upgrade — add users, profiles, notes & status

Extend init_db() in app.py to add: candidates table (id, name, email, created_at), candidate_skills (candidate_id, skill), and a notes + status column on applications. Use ALTER TABLE … ADD COLUMN IF NOT EXISTS so existing rows are untouched. Also add a roadmaps table (candidate_id, job_id, steps JSON, created_at).

app.pydatabase.db
Expand the skill vocabulary in resume_parser.py

Grow KNOWN_SKILLS from 28 to 80+ terms covering cloud, DevOps, data science, frontend, and soft skills. Add synonym normalization (e.g. "js" → "javascript"). This powers all downstream extraction immediately.

utils/resume_parser.py
Build a roadmap_agent.py — personalized learning roadmaps

New agent in agents/roadmap_agent.py. Takes missing_skills list, returns structured JSON with: stage (Foundation / Intermediate / Advanced), skill, suggested resource type (video / practice / project), estimated days, and a short rationale. Hardcoded resource catalog initially (no external API needed). Returns ordered stages grouped by priority.

agents/roadmap_agent.py
Upgrade skill_analyzer.py to use the roadmap agent

Import roadmap_agent and replace the flat "Learn the basics of X" list with structured roadmap steps. Keep the same function signature so no routes break. Add a priority_order field that sorts missing skills by job-market demand weight.

agents/skill_analyzer.py
Upgrade career_assistant.py — richer English + full Kannada routing

Replace the single static Kannada string with a topic-routing table mirroring the English rules (resume, interview, skills, roadmap, greeting, fallback) — all in Kannada. Add new English topics: salary negotiation, portfolio advice, LinkedIn profile. Keep the same career_reply(message, language) signature.

agents/career_assistant.py
Add an orchestrator agent — agents/orchestrator.py

A thin coordinator that accepts a pipeline_request dict and routes to the right sequence of agents: resume upload → skill extraction → job matching → skill-gap analysis → roadmap generation. Returns a unified pipeline_result dict. No circular imports; agents remain independent. This is the "agentic AI" architecture layer.

agents/orchestrator.py
New Flask routes: /dashboard, /api/roadmap, /api/pipeline, /application/<id>/status

/dashboard shows candidate name, extracted skills, saved applications, and active roadmaps in one view. /api/roadmap accepts current + required skills and returns full structured roadmap. /api/pipeline runs the full orchestrator end-to-end from uploaded resume. /application/<id>/status is a PATCH endpoint to update status and notes.

app.py
Resume upload UI — new section in index.html

Add a "Upload your resume" card with a file-picker (accept=".pdf,.docx,.txt"), a submit button, and a result panel that shows extracted skills as chips, a match preview against the top job, and a "Run full analysis" button. The panel is revealed progressively via JS fetch to POST /resume.

templates/index.htmlstatic/js/app.js
New template: templates/dashboard.html

Candidate dashboard with four panels: (1) Skill profile — chips for each extracted skill. (2) Top matched jobs — top 3 with scores. (3) Active learning roadmap — stage-by-stage visual checklist. (4) Application pipeline — kanban-style status columns (Saved / Applied / Interviewing / Offered). All data injected server-side via the /dashboard route.

templates/dashboard.html
New template: templates/roadmap.html

Standalone roadmap page. Takes a job title and candidate skills from query params, calls /api/roadmap on load, renders an ordered step-by-step learning path with stage labels, estimated days, and resource type icons. Linked from job cards and the dashboard.

templates/roadmap.html
Upgrade tracker.html — editable status & notes

Add inline status dropdowns (Saved / Applied / Interviewing / Offered / Rejected) and a notes textarea per application row. Submits via fetch PATCH /application/<id>/status on change. Add per-status colour badges matching the dashboard kanban colours.

templates/tracker.htmlstatic/js/app.js
Extend nav and CSS — add Dashboard, Resume, Roadmap links

Add "Dashboard" and "Roadmap" links to base.html nav. Extend style.css with: roadmap stage cards, skill chip styles, kanban status columns, dashboard grid, and progress bars — all using the existing CSS variable system (--blue, --ink, etc.).

templates/base.htmlstatic/css/style.css
Update requirements.txt and README.md

No new external pip packages are required — the upgrade uses only Flask, Werkzeug, pypdf, and python-docx already installed. Update README.md with new routes, features, and setup notes.
